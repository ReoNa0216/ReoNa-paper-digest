# 润色后科学复核

在 02-polished 完成后读取。审查目标是找出可影响读者理解的事实、推理和语义变化；不能用“去 AI 味完成”代替审查，也不能把所有论文都审成湿实验 SOP。

## 通用复核

回到原始来源而非只看初稿，逐项检查关键主张的证据、每个数字和单位、比较对象、物种/人群、实验单位与时点、肯否定和不确定性。确认主要问题的去向，引用能定位，事实/解释/假设/用户观点身份未混淆。逐段比对初稿和润色稿，特别留意限定条件是否被删、主动语态是否虚构了执行主体。

## 按设计选项

| 类型 | 优先核查 |
|---|---|
| 湿实验/细胞工程 | biological vs technical replicate，处理/对照，纯度与产量分母，体内外层级，功能端点与机制证据 |
| 临床/人体研究 | 试验阶段与设计，入组和分析人数，剂量单位，主要/探索端点，随访、安全性观察边界；不据此提供个人临床建议 |
| 单细胞/组学 | 细胞数与供者数，批次与整合，注释依据，差异统计单位，多重比较，相关与机制验证 |
| 方法/计算 | 基线、训练/验证/测试独立性，数据泄漏，评价指标，消融与外部验证，计算或测量条件 |
| 综述/多论文比较 | 原始证据与综述解释分开，研究间设计和指标可比性，矛盾结果不被抹平，不能拼接不同研究得到未做过的因果实验 |

只使用相关项；不为不适用的检测、设备或临床指标制造缺口。

## 审查记录与门禁

在 `analysis/review.md` 记录实际检查范围、关键问题、来源位置、修改前后与残余限制。检查没有发现问题时也要写清核查了什么，不能只写“全部通过”。修复稿保存为 03-reviewed 和 article.md，然后生成当前 fingerprint，把摘要填入审核记录。

```yaml
schema_version: 1
verdict: approved
reviewer: "Codex；注明本次实际核查范围，不伪称独立专家评审"
reviewed_at: "实际 ISO 日期/时间"
profiles: [wetlab]  # 按实际设计选择，可多选
checks:
  sources: checked
  claims: checked
  numbers_units: checked
  scope_causality: checked
  voice: checked
  coverage: checked
limitations: []     # 未解决限制如实列出，可为非空
fingerprints: {}    # 粘贴 pipeline.py fingerprint 的完整映射
```

不能直接照抄示例并视为审核通过。存在需要修正的重要事实问题时 verdict 为 blocked，先修复再审核。含明确限制的合格稿可以 approved，但 limitations 与正文边界必须一致。

fingerprint 覆盖最终正文、账本、原始来源清单、参考文献、讨论/事实/结构图、审查说明和语义元数据，以及被正文/封面使用的本地图片。meta 的 status 不参与摘要，避免本地构建状态变化无意义地使审核失效。稿件或证据变化后原审核自动失效；不得为绕过检查而仅刷新摘要。

通过脚本意味着“材料完整且审核记录与当前版本匹配”，不意味着脚本验证了科学真实性。复核没有读取原论文、关键图或补充材料时必须说明，不能写完整科学审核已完成。

## 页面 QA 与交付

构建后检查标题、摘要、正文与图注的一致性，页面内容哈希相同；视觉查看桌面和窄屏、上标、中文字体、长表格和图片。测试复制时区分 HTML/纯文本写入与降级选中分支。有浏览器权限就实际测，无权限则注明未测，不把代码存在当作功能验证。

本地浏览器复制验证不等于微信粘贴验证；没有实际打开并粘贴到微信后台时，交付说明不能声称已完成该项。构建失败不改变发布状态，也不把部分产物当成完成稿。
